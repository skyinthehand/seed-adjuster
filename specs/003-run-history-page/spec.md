# Feature Specification: 実行履歴ページ

**Feature Branch**: `003-run-history-page`

**Created**: 2026-09-15

**Status**: Draft

**Input**: User description: "実行・設定ページとは別に履歴ページを作って、過去の実行へのリンクを残せるようにしたい"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 過去の実行を一覧から見つけて開く (Priority: P1)

大会運営者が、以前実行したシード自動調整の結果ページを開きたいが、実行完了時に表示された結果URLを保存し忘れていた。運営者は「実行」ページ・「設定」ページとは別に用意された「履歴」ページを開き、過去に実行した調整の一覧から目的の実行を見つけて、その結果ページへ直接移動する。

**Why this priority**: これは本フィーチャーの中核的価値そのものである。現状、結果ページのURLを実行直後に保存し忘れると、その実行結果に到達する手段がない(対象を一意に指すtargetIdを事前に知っていない限り、同一対象内の実行一覧すら辿れない)。この一覧ページがなければ本フィーチャーは意味をなさない。

**Independent Test**: 実行を1件完了させた後、結果URLを保存せずに履歴ページを開き、一覧からその実行を選んで結果ページに到達できることを確認する。

**Acceptance Scenarios**:

1. **Given** 過去に成功した実行が1件以上ある状態、**When** 運営者が履歴ページを開く、**Then** 実行日時が新しい順に、各実行の識別情報(使用した設定名・対象・実行日時・ステータス)が一覧表示される。
2. **Given** 履歴ページに実行の一覧が表示されている状態、**When** 運営者が成功した実行の項目を選択する、**Then** その実行の結果ページへ遷移する。
3. **Given** 過去の実行が1件も存在しない状態、**When** 運営者が履歴ページを開く、**Then** 「まだ実行履歴がありません」等、一覧が空である旨がわかるメッセージが表示される。

---

### User Story 2 - 大量の履歴から目的の実行を絞り込む (Priority: P2)

運営を続けるうちに実行回数が増えていく。運営者は、設定名や対象(スプレッドシート・大会)で履歴を絞り込み、目的の実行を素早く見つけたい。

**Why this priority**: 一覧が数十件を超えると、絞り込み手段がなければ目的の実行を探す負担が大きくなり、P1で実現した「見つけて開く」という価値が実用に耐えなくなる。ただし初期の利用件数では一覧をそのまま眺めるだけでも成立するため、P1より優先度は下げられる。

**Independent Test**: 異なる設定名で複数回実行した状態で、履歴ページ上である設定名を指定して絞り込み、その設定名に該当する実行のみが表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 複数の設定名にまたがる実行履歴がある状態、**When** 運営者が特定の設定名で絞り込む、**Then** その設定名を使用した実行のみが一覧に残る。
2. **Given** 一覧の件数が1画面に収まらないほど多い状態、**When** 運営者が一覧をさらに下にたどる操作を行う、**Then** 続きの(より古い)実行が追加で表示される。

---

### User Story 3 - 失敗した実行も履歴から把握する (Priority: P3)

運営者は、成功した実行だけでなく、途中で失敗した実行についても「いつ・どの設定で失敗したか」を履歴から把握し、原因調査や再実行の判断に役立てたい。

**Why this priority**: 失敗の把握は運用上有用だが、P1(過去の成功結果を辿る)ほど日常的な必須操作ではないため、P3とする。

**Independent Test**: 失敗した実行を1件発生させた後、履歴ページの一覧にその実行が「失敗」というステータス付きで表示され、結果ページへのリンクは提供されない(または無効化されている)ことを確認する。

**Acceptance Scenarios**:

1. **Given** 失敗ステータスの実行が1件ある状態、**When** 運営者が履歴ページを開く、**Then** その実行が「失敗」であることがわかる表示とともに一覧に含まれる。
2. **Given** 失敗した実行の項目が一覧にある状態、**When** 運営者がその項目を選択しようとする、**Then** 結果ページへは遷移せず、失敗した実行であることが再度わかる(結果が存在しないことによる混乱を避ける)。

---

### Edge Cases

- 進行中(まだ完了していない)実行は履歴一覧にどう表示されるか → 「実行中」ステータスとして表示され、結果ページへのリンクはまだ提供されない。
- 同じ対象・同じ設定名で短時間に何度も実行した場合、一覧はすべての回を個別の項目として残す(実行ごとに一意な識別子を持つため)。
- 一覧の取得中にエラーが発生した場合、既存の他ページ同様、エラー内容がわかるメッセージを表示し、再読み込みできる手段を示す。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、「実行」ページおよび「設定」ページとは独立したナビゲーション項目として「履歴」ページを提供しなければならない。
- **FR-002**: 履歴ページは、過去に作成された実行(進行中・成功・失敗のすべて)を、実行日時が新しい順に一覧表示しなければならない。
- **FR-003**: 一覧の各項目は、その実行を識別・区別できるだけの情報(使用した設定名、対象の入力方式(Googleスプレッドシート/start.gg)、実行日時、ステータス(実行中/成功/失敗))を含まなければならない。
- **FR-004**: 一覧の各項目のうちステータスが「成功」であるものは、選択するとその実行の結果ページへ遷移できなければならない(FR-012bで定義済みの公開結果ページと同一のもの)。
- **FR-005**: ステータスが「失敗」または「実行中」の項目は、結果ページへのリンクを提供してはならない(結果がまだ存在しない、または今後も存在しないため)。
- **FR-006**: 履歴が1件も存在しない場合、システムはその旨をわかりやすく示す空状態メッセージを表示しなければならない。
- **FR-007**: 履歴ページは、設定名による絞り込みができなければならない。
- **FR-008**: 一覧が1画面に収まらない件数になった場合、システムは追加の履歴を段階的に取得・表示する手段(さらに読み込む操作など)を提供しなければならない。
- **FR-009**: 履歴ページは、制御プレーンに記録された全実行を一覧表示の対象としなければならない(対象・設定名を問わず、既存の公開結果ページ(FR-012b)と同様に認証なしで誰でも閲覧可能とする)。特定のブラウザ・端末が過去に自ら作成・閲覧した実行に限定してはならない。
- **FR-010**: 履歴一覧の取得に失敗した場合、システムはエラーの発生をわかりやすく示し、再試行できる手段を提供しなければならない(既存の他ページにおけるエラー表示方針との一貫性を保つ)。

### Key Entities

- **実行履歴一覧項目**: 既存の「実行(AdjustmentRun)」エンティティ(仕様書001参照)を履歴ページ向けに表示するための投影。実行ID、使用設定名、対象の入力方式、作成/開始/完了日時、ステータス、(成功時のみ)結果ページへの参照を持つ。新しい永続データを追加するものではなく、既存の実行記録の見せ方を追加するものである。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 結果URLを保存し忘れた運営者が、履歴ページを開いてから目的の過去の実行結果に到達するまで1分以内で完了できる。
- **SC-002**: 実行履歴が0件の状態でも、履歴ページはエラーにならず、空である旨が明確に伝わる。
- **SC-003**: 実行履歴が50件を超える状態でも、設定名による絞り込みにより、運営者は目的の実行を一覧の先頭付近(スクロール操作を最小限に)で見つけられる。
- **SC-004**: 失敗した実行についても、運営者はその発生日時と使用設定名を履歴ページから把握できる。

## Assumptions

- 履歴ページは既存の「実行」ページ・「設定」ページと同様、認証を必要としない(現行方式に合わせる、FR-012b相当)。
- 一覧に表示する実行の並び順は「新しい順」を既定とし、古い順への切り替えなど追加のソート手段は本フィーチャーの必須範囲に含めない。
- 失敗した実行についても一覧に含める(成功した実行のみに限定しない)。ただし結果ページへのリンクは成功時のみ提供する(FR-004, FR-005)。
- 絞り込みは設定名を軸とする(FR-007)。対象(スプレッドシートID等)そのものによる絞り込みは、設定名絞り込みで多くの場合代替できるため必須要件としない。
- 段階的な追加読み込み(FR-008)の具体的な一度あたりの件数は、実装時に妥当な値(例: 20〜50件程度)を選定する。
